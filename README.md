> BUCT Graduation Project Repository  
>
> 主题：基于 Aspen 的 PET 工艺过程模拟、文献管理、论文、图纸与答辩归档

## 当前状态

- 默认分支：`main`
- 最新版本：`6.14.1`
- 当前阶段：**答辩完成，毕业设计归档完成**
- 更详细的阶段变化请见 [`CHANGELOG.md`](./CHANGELOG.md)



## 项目简介

本仓库用于集中管理毕业设计全过程中的核心数字资产，尽量把“过程模拟、资料整理、论文写作、图纸绘制、答辩准备、最终归档”放在同一套 Git 历史中追踪。仓库内容主要包括：

- Aspen Plus（基于 Polymer Plus）过程模拟工程文件
- 灵敏度分析结果与关键参数调整记录
- 文献快照、Zotero 导出文件与学校要求模板
- 开题报告、文献翻译、中期报告、论文终稿与答辩素材
- 工艺物料流程图（PFD）、管道及仪表流程图（P&ID）、工艺条件图和设备布置图
- 与项目有关的 AIGC 存档、自动化脚本和 CAD 辅助工具
- 最终提交材料、查重结果、纸质归档扫描件和过程性素材归档

本仓库的目标不是把所有专有软件流程完全自动化，而是尽可能做到：

- **可追踪**：关键改动能在 Git 提交、版本号与更新日志中找到来源
- **可复现**：核心 Aspen 工程、参数依据与分析结果有对应存档
- **可交付**：论文、图纸、答辩、查重与归档材料能从仓库中集中找到
- **可移交**：最终材料另有汇总目录，便于毕业资料打包、核对和长期保存

## 目录说明

### `论文和答辩/`

集中存放 CAD 图纸源文件与导出的正式 PDF。

### `杂项/存档汇总/`

用于最终提交和移交的集中汇总目录。当前包含：

- 论文 PDF 版和 Word 版
- 图纸 PDF 汇总
- 开题报告、中期报告、文献翻译和文献原文
- 查重报告
- 答辩 PPT、答辩记录和绿皮册

该目录偏向“最终交付包”，不是工作源文件目录。若需要追溯具体写作和修改过程，应回到 `论文和答辩/`、`图纸/` 与 `过程模拟/` 查看源文件。

### `杂项/AIGC/`

保存与项目有关的 AI 辅助记录，包括参数解释、文献摘录整理、灵敏度分析思路与提示词等。

说明：AIGC 文件用于辅助记录和追溯思路，不应替代文献、软件结果或指导教师意见作为最终依据。

### `杂项/Automation/` 等目录...

保存数据整理、CAD 辅助和管道选择相关的过程工具。

- `Automation/`：用于将 Aspen 导出的流股数据同步到 PFD 图纸中，全链条自动化。
- `CadConnector/`：用于从 CAD 标注中导出文本信息、辅助 P&ID 仪表编号等操作
- `PipeSelector/`：用于管道选择、去重、汇总和导出管道一览表

### `Assets/`

保存版本截图与非核心过程素材。

- `Versions/`：重要版本节点截图
- `Useless/`：废稿、彩蛋和非正式素材，仅作归档，不作为正式成果

说明：本节保留原项目目录介绍，脱敏版不包含 Assets 目录及其文件。

## 推荐软件环境

本仓库中包含较多专有格式文件，完整使用建议具备以下软件环境：

- **Aspen Plus**：用于打开与编辑过程模拟工程
- **AutoCAD**：用于查看和编辑 `.dwg` 图纸
- **Typst**：用于继续编译论文源文件
- **Zotero**：用于导入和管理文献库
- **Office / PDF 阅读器（Edge）**：用于查看报告、演示稿、论文及 PDF 文档
- **Git**：用于版本管理、分支协作与阶段归档

说明：本仓库以“资料管理 + 过程留痕 + 最终归档”为主，完整复现仍依赖授权软件环境。



## Git 工作流约定

### 分支建议

- `main`：稳定主线，保存当前整理后的可用版本
- `sync-from-desktop`：跨设备同步资料时使用的临时整理分支

### 提交信息规范

采用简化版规范提交格式：

```text
<type>(<scope>): <summary>
```

常用类型：

- `feat`：新增功能或新增阶段成果
- `fix`：修正参数、图纸、流程或错误
- `docs`：修改 README、CHANGELOG、论文、文献说明等
- `refactor`：重构目录结构、统一命名、整理文件布局
- `chore`：杂项维护，如 `.gitignore`、缓存清理、归档汇总等

示例：

```text
feat(Aspen): 增加真空系统并调整流程
feat(CAD): 新增正式图纸导出
docs(cite): 上传参考文献快照
refactor(repo): 重构文件结构、修正链接
chore(archive): 汇总毕业设计归档材料
```

### 版本号约定

使用语义化版本号形式：

```text
vMAJOR.MINOR.PATCH
```

当前项目内的实际约定为：

- `MAJOR`：按月份赋值
- `MINOR`：按日期赋值
- `PATCH`：用于同日多次提交做区分

版本发布和里程碑记录在 [`CHANGELOG.md`](./CHANGELOG.md) 中。



## 注意事项

- `.apwz`、`.dwg`、`.pdf`、`.pptx`、`.docx` 等二进制文件不易做差异比较，提交前建议确认文件名和目录位置无误
- 本项目参考文献使用 Zotero 管理和同步，仓库内当前保留 `rdf`、`bib` 及部分常用 PDF 快照，并非完整文库镜像
- `杂项/存档汇总/` 是最终材料汇总入口；源文件、脚本和过程记录仍以原目录为准
- 跨设备作业时，建议先 `pull` 最新主线，再开分支同步，最后合并回 `main`
- 对于大型二进制资产，后续如有需要可考虑引入 Git LFS
- `Assets/Useless/` 属于过程归档，不建议在正式版本说明中作为主要成果引用

# 任务说明

## 1. 文档目标

编写一个化工管道编号解析器（简单的、个人使用的HTML应用）

## 2. 页面目标与用户故事

- 页面中间偏上放置一个大输入框，供用户输入完整管道编号，如 `EG-1405-25-L1B-30H`。
- 大输入框下方实时显示对照表，解释每一段的含义。
- 若某字段是枚举值，则用下拉框；若某字段是数字，则用数字输入框；复合字段在同一行展示其子字段控件。
- 用户修改任一控件后，应立即同步回大输入框。
- 页面风格为简洁、清淡、低饱和度。

## 3. 编码总体模型

标准中的“管道组合号”由 6 个单元组成，其中前 3 个单元合并构成“管段号”。在网站中，建议按 5 段展示与编辑：

```text
{物料代号}-{主项编号+管道序号}-{管道规格/管径}-{管道等级}-{绝热/隔声代号}
```

对应完整示例：

```text
EG-1405-25-L1B-30H
```

拆解如下：

- `EG`：物料代号
- `1405`：主项编号 `14` + 管道序号 `05`
- `25`：管道规格/管径
- `L1B`：管道等级
- `30H`：绝热/隔声代号





# 管道编号解析说明

## 1. 推荐支持范围

V1 推荐优先支持以下能力：

1. 解析完整格式  
   `物料代号-主项编号+管道序号-管径-管道等级-绝热/隔声代号`

2. 兼容简化格式  
   `物料代号-主项编号+管道序号-管径`

3. 表单与大输入框双向同步：
   - 用户改大输入框，实时反解析
   - 用户改任一字段，实时回写完整编号

4. 未知但结构合法的枚举值不报错，保留原值并标记：
   - `isCustom: true`
   - `status: "pending_confirm"`

---

## 2. 标准化后的数据模型

建议统一输出为如下结构：

```json
{
  "raw": "EG-1405-25-L1B-30H",
  "normalized": "EG-1405-25-L1B-30H",
  "form": "full",
  "segments": {
    "materialCode": "EG",
    "unitNo": "14",
    "lineSeq": "05",
    "unitAndSeq": "1405",
    "pipeSize": "25",
    "pipeClass": "L1B",
    "pressureGradeCode": "L",
    "classSequenceNo": "1",
    "materialCategoryCode": "B",
    "insulationCode": "30H",
    "insulationThickness": "30",
    "insulationType": "H"
  }
}
```

---

## 3. 分段规则

完整编号按 5 段处理：

```text
{materialCode}-{unitNo+lineSeq}-{pipeSize}-{pipeClass}-{insulationCode}
```

示例：

```text
EG-1405-25-L1B-30H
```

拆分逻辑：

- `EG` → `materialCode`
- `1405` → 前 2 位 `unitNo`，后 2 位 `lineSeq`
- `25` → `pipeSize`
- `L1B` → `pressureGradeCode + classSequenceNo + materialCategoryCode`
- `30H` → `insulationThickness + insulationType`

---

## 4. 必须遵守的规范化规则

### 4.1 大小写
所有字母统一转大写。

### 4.2 补零
- `unitNo` 固定 2 位，不足补零
- `lineSeq` 固定 2 位，不足补零

例如：

- `14` → `14`
- `5` → `05`

### 4.3 写回格式
完整格式固定写回为：

```text
{materialCode}-{unitNo}{lineSeq}-{pipeSize}-{pipeClass}-{insulationThickness}{insulationType}
```

简化格式写回为：

```text
{materialCode}-{unitNo}{lineSeq}-{pipeSize}
```

---

## 5. 校验建议

建议将“结构校验”和“枚举校验”分开：

### 5.1 结构校验
- `materialCode`: `^[A-Z]{1,3}$`
- `unitNo`: `^[0-9]{2}$`
- `lineSeq`: `^[0-9]{2}$`
- `unitAndSeq`: `^[0-9]{4}$`
- `pipeSize`: `"^[0-9]+([xX×][0-9.]+)?$|^[0-9]+(\\\")?$"` V1 可先支持纯数字 `^[0-9]+$`
- `pipeClass`: `^[A-Z][1-9][A-Z]$`
- `insulationCode`: `^[0-9]+[A-Z]$`

### 5.2 枚举校验
结构合法后，再判断是否命中定义表：
- 命中：返回标准标签
- 未命中：保留原值，不自动替换

---

## 6. 推荐程序行为

### 6.1 parse(code)
输入字符串，输出：
- `ok`
- `form`
- `normalized`
- `segments`
- `display`
- `errors`
- `warnings`

### 6.2 compose(data)
输入字段对象，输出标准化编号字符串。

### 6.3 explain(parsed)
基于枚举表返回可直接渲染的解释对象。

---

## 7. UI 最小约束

建议前端直接按定义文件中的 `segments` 元信息渲染：

- 枚举字段：`select`
- 数值字段：`number`
- 复合字段：同一行展示子字段
- 未知代码：弱提示，不阻塞输入
- 页面视觉：简洁、低饱和度、留白充分

---
